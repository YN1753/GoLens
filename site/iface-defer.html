Interface 与 defer

Interface 用类型信息 + 数据实现动态派发；defer 在注册时求值参数，在返回/panic 时按 LIFO 执行，可与 panic/recover 组成错误展开路径。

Interface 心智模型

  • 空接口 interface{} / any：类型 + 数据。
  • 非空接口：方法表（itab）+ 数据；调用是间接的。
  • 类型断言 x.(T)、switch x.(type) 提取具体类型。
  • nil 接口与「接口里装着 nil 指针」不是一回事（经典坑）。

defer / panic / recover

  • defer 参数立即求值；函数体延后执行。
  • 多 defer：后进先出。
  • panic 触发后仍执行 defer；同 defer 中 recover 可止住。
  • goroutine 顶层未 recover 的 panic 会导致进程崩溃。

交互 Lab · defer 栈

怎么用：多次「注册 defer」→「运行」看 LIFO；再试「模拟 panic」+ recover 开关。

常见追问

为什么 nil 接口方法调用会 panic？

动态类型为空时无法派发方法；「类型非空但值为 nil 指针」则是另一类坑。

defer 里能改返回值吗？

命名返回值可以；匿名返回值在 defer 中修改通常看不见（除非用命名结果）。

速查表

  • iface ≈ 类型/方法表 + 数据；动态派发
  • defer：参数即刻求值；执行 LIFO
  • panic 仍跑 defer；recover 可止住
  • 接口 nil ≠ 值 nil

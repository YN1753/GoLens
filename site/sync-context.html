sync 与 Context

sync 解决共享内存的互斥与协作（锁、等待组、只初始化一次）； context 解决跨 API 的取消与超时，以树形信号向下传播，避免 goroutine 泄漏。

sync 原语速览

原语用途面试一句
Mutex临界区互斥Lock/Unlock 成对；可用 defer Unlock
RWMutex多读一写读多写少时吞吐更好
WaitGroup等一组 goroutineAdd 在启动前；Done；Wait
Once只执行一次初始化Do 内 panic 也会视为已执行（注意）
atomic无锁计数等简单计数器优先 atomic

Context 树

根是 context.Background()（或 TODO()）。派生节点： WithCancel / WithTimeout / WithDeadline / WithValue。 父取消 → 子树取消；子取消不影响父。

工程习惯

请求入口创建 ctx，函数签名第一个参数传 ctx；底层用 select <-ctx.Done() 或支持 ctx 的库退出。不要用 context 传可选业务参数当配置中心。

常见追问

为什么不能把 Mutex 按值传递？

复制锁会破坏互斥语义，应传指针或放在结构体中由指针持有。

WithValue 适合放什么？

请求级元数据（trace id 等），不适合放可选配置或大对象。

WaitGroup 可以 Add 负数吗？

Done 等价 Add(-1)；计数不能为负，否则 panic。

速查表

  • Mutex/RWMutex：共享内存互斥；WaitGroup：等人齐
  • Once：初始化一次；简单计数用 atomic
  • Context：取消/超时向子树传播
  • ctx 做函数首参；Done 协调退出，防泄漏

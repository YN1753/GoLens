Chapter 01

GMP 调度

Go 用 G（goroutine）承载任务、P（逻辑处理器）持有可运行队列、M（OS 线程）真正执行；调度的本质是让 M 尽快从某个 P 的队列里拿到 G。

为什么需要 GMP

若每个 goroutine 都绑死一条 OS 线程，海量协程会把线程栈和切换成本打爆。 Go 把「可运行的 G」和「执行用的 M」解耦，中间用数量有限的 P 做缓冲与本地化： GOMAXPROCS 决定 P 的个数，也就是同时能有多少 M「持有调度上下文」。

三个角色

角色是什么面试关键句
G Goroutine，含栈、指令指针、状态 用户态轻量执行体；栈可从 2KB 增长
P Processor，逻辑处理器，持有本地运行队列等资源 P 数量 = GOMAXPROCS；没有 P 就不能调度用户 G
M Machine，OS 线程 M 要绑定 P 才能跑 G；阻塞时可能与 P 解绑

队列与偷取

每个 P 有 runnext（下一只优先跑的 G，通常 1 个坑位）和 本地队列（历史上常见上限 256）。 本地满了会推一半到全局队列。P 空了会先看全局队列，再随机偷其他 P 本地队列的一半——这就是 work stealing。

阻塞时发生什么

G 进入阻塞（如 channel、系统调用）后，M 可能带着 G 挂起；调度器会为 P 另找 M，保证吞吐不塌。系统调用场景下常见「M 与 G 绑住、P 被挪走」的叙述。

findrunnable 伪代码（面试版）

// 简化，非源码逐行
schedule():
  for {
    // 1) 本地 runnext / 本地队列
    if g := p.runnext; g != nil { return g }
    if g := localQueue.poll(); g != nil { return g }
    // 2) 全局队列（按需批量取）
    if g := globalQueue.poll(); g != nil { return g }
    // 3) 从其他 P 偷一半
    if g := stealWork(p); g != nil { return g }
    // 4) 都没有：自旋或休眠，等 netpoll / 新任务
  }

G 的状态（高频）

状态含义典型来源
_Grunnable可运行，在队列里新建、唤醒、被偷入队
_Grunning正在 CPU 上跑M 成功调度到
_Gwaiting等待中channel / mutex / select 无就绪
_Gsyscall系统调用中阻塞 syscall；P 可能被拿走
_Gdead已结束函数返回

栈如何增长

  • 初始栈很小（KB 级），不够时分段栈/连续栈扩容（版本演进后多为连续栈复制扩容）。
  • 扩容时调整指针，对业务透明；深递归仍要防爆栈。
  • runtime.GOMAXPROCS 不改单个 G 的栈策略，只改 P 数量。

与 netpoll / GC 的衔接

  • IO 等待：G 让出，netpoll 就绪后再入 runq（见 Netpoller 章）。
  • GC：标记期辅助分配（assist）可能插入 G 的执行；大量分配会抬高 GC 压力。
  • 抢占：长时间不进入调度点的 G 可能被异步抢占（Go 1.14+），避免饿死 GC/其他 G。

常见追问（加深）

P 与 CPU 核的关系？

P 是逻辑处理器，数量默认跟 GOMAXPROCS（常等于核数）相关；它是调度上下文，不等于「一个线程绑死一个核」。

全局队列为什么还要「每隔一段时间看一眼」？

若只靠本地+偷取，全局里的任务可能被饿死。调度循环会按一定策略检查全局队列，保证公平。

锁与 channel 会不会让 P 空转？

阻塞的 G 会让 M 去跑别的；真正空转的是「无事可做」时的 spinning M，数量有限。

常见追问

GOMAXPROCS 调大就一定更快吗？

不一定。它控制 P 数，影响并行度；若负载以锁竞争、内存带宽或短 CPU 片段为主，盲目调大可能增加切换与缓存失效。

runnext 有什么用？

把「刚创建/刚唤醒的 G」放在 P 的下一执行位，改善局部性，减少进本地队列再取的开销。

work stealing 偷多少？

常见叙述是偷对方本地队列的一半（配合 runnext），降低失败概率并避免两边反复空转。

没有 P 的 M 在干嘛？

可能在自旋寻找可运行 G，或进入休眠等待被唤醒。面试答「spinning / parked」关键词即可。

速查表

  • G = goroutine；P = 逻辑处理器（GOMAXPROCS）；M = OS 线程
  • P 本地队列 + runnext；溢出推全局；空了找全局 / 偷其他 P
  • M 必须持有 P 才能调度用户 G
  • channel / syscall 阻塞可能导致 M–P 分离，调度器另起 M
  • 目标：高吞吐、低延迟地把可运行 G 丢到核上

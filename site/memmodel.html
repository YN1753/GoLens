内存模型与 happens-before

Go 内存模型回答「一个 goroutine 的写，另一个何时能看见」。 同步原语（channel / mutex / once / atomic）建立 happens-before； 否则可能是数据竞争，行为未定义。

核心规则（速记）

同步点happens-before 直觉
go f() 前的写在 f 开始前可见
channel send先于对应 recv 完成
mutex.Unlock先于之后的 Lock
once.Do 返回init 的写对其它观察者可见
atomic store/load按原子操作序提供可见性
检测

go test -race / 带 -race 运行，发现竞争就当 bug 修，不要赌「应该没事」。

反例

// 错误：无同步的标志位
var done bool
go func() { x = 42; done = true }()
for !done {} // data race；x 未必可见

// 正确：channel 或 mutex
ch := make(chan struct{})
go func() { x = 42; close(ch) }()
<-ch
// 此处读 x 安全

Slice 与 Map 底层

Slice 是指向底层数组的头 + len + cap 描述符；append 可能扩容搬家，子切片可能与父共享数组。 Map 是哈希表：桶 + 溢出桶 + 扩容搬迁，访问 O(1) 建立在良好哈希与负载因子上。

Slice 三元组

写 s := make([]int, 1, 4) 时得到：指针指向一段连续数组，len=1 表示可见长度，cap=4 表示不扩容还能 append 的空间。

append 与扩容

len < cap：就地写入。否则分配更大数组（常见策略是容量翻倍，小切片阶段有更细的增长表），拷贝旧数据后再写入。扩容后旧数组与新切片不再共享。

共享底层数组陷阱

t := s[1:3] 往往与 s 共用数组。向 t 写入，s 的重叠区间也会变。需要隔离时使用 copy。

Map 直觉

  • key 经哈希映射到桶；桶内再精确比较 key。
  • 负载过高会扩容：新建更大桶组，逐步搬迁。
  • 并发读写 map 会 panic——要么加锁，要么用分片 / sync.Map（场景特殊）。
  • 遍历顺序故意随机，不能依赖。

常见追问

append 一定会分配新数组吗？

不一定。len < cap 时原地写；只有容量不够才搬家。

为什么 range map 顺序不稳定？

运行时故意随机化起点，避免程序依赖遍历顺序。

nil slice 和 empty slice？

都能 len==0；nil 的指针为 nil。append 对两者通常都能工作。

速查表

  • slice = ptr + len + cap；cap 不够 append 才扩容
  • 子切片可能共享底层数组 → 写入互相影响
  • 隔离用 copy；map 并发读写会 panic
  • map：桶 + 溢出桶 + 扩容搬迁；遍历顺序随机
